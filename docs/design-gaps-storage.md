# Storage Open Gaps

- Does the per-entity `RowProperties` name scan need a different representation for rows with many properties? A row read and removal visit only that row; a named read scans its names, and a one-property row still allocates its row array.
- Which measured callers require a different `GraphEntityCache` wrapper lifetime? The current cache uses SoftReference, so replacing it needs retained-heap and allocation evidence.
- Can `AbcJgraphtStorage.deleteNode` collect property/mapping cleanup once while `removeVertex` performs topology deletion, instead of traversing incident edges twice?
- Which caller needs a different JGraphT property-map return contract? Current `getNodeProperties` and `getEdgeProperties` copy their outer maps; a live view would change the collection lifetime contract.
- Do boxed integer keys in JGraphT structural maps justify primitive-keyed maps on a measured workload?
- Would a MapDB per-edge composite key avoid full identity-set serialization without changing reopen and export contracts?
- Would MapDB native primitive serializers or a whole-row property value improve a measured workload enough to justify different collection layouts?
- How much does MapDB `concurrencyDisable()` change a fixed workload’s cost after serialization is included?
- Can Neo4j `transferTo` use a bounded transaction scope while preserving its error and resource-lifetime contracts?
- Which Neo4j properties can use native values without changing the `IValue` serialization contract?
- Can `Neo4jEntityProperties.keys` remove its distinct operation while preserving reserved-name filtering?
- Which profile evidence attributes time to locking, serialization, allocation or transaction commit in each backend? Retained benchmark throughput alone does not establish those causes.

## Typed Storage Implementation

The [capability adapters](design-storage-capabilities.md) provide guarded readers/writers and captured compatibility snapshots over the present layered implementation. Registered fields and indexed families use `StorageSchema` with the existing entity rows. The physical adjacency and capacity/budget parts of the [typed selection/Freeze algorithm](spec-storage.md#typed-selection-and-freeze) remain implementation work. Availability of an API does not establish acceptance of an implementation.

- `StorageAccess` captures mutable values at admission and compatibility reads and confines borrowing to guarded callbacks over `LayeredStorage`. Registered fields, scoped cell readers and immutable `PropertyValue` transport are available over schema-configured layered storage. Direct native/concurrent capability constructors remain absent. Existing `RowProperties` supplies entity-local rows and local name scans; any representation change builds on that implementation.
- `LayeredStorageImpl` and `FrozenLayer` retain four boxed ID maps and a mutable translated-edge cache. Their in-memory Freeze transfers captured registered rows without a codec cycle; external frozen stores use the compatibility transfer boundary. The chosen read-only builder/CSR path, checked capacity, stale-handle rejection and old+new+workspace budget/failure guarantees are missing. No concurrency failure is claimed as reproduced merely from the cache's source.
- `EdgePropertyFamilies`, `ActiveLayer` and `LayerStack` implement the fixed compatibility family; registered indexed families retain immutable sorted primitive-ID membership and scoped typed cells. The [typed family](design-storage-families.md#typed-indexed-families) must preserve complete first-active reset through point/row reads, Freeze and revert.
- `TagAdjacencyIndex`, `EdgePairIndex` and `FrozenEdgeOrder` already select groups/pairs and preserve encounter order. Typed adjacency directories and primitive adjacency vectors are pending measured changes, not missing public selection. Order-preserving removal/merge overhead and temporary compatibility snapshots must be included.
- `LayeredStorageImpl.addRevertListener` retains registrations for its storage-owned graph lifetime; `close` clears data and releases those registrations. Adapter guard composition retains the existing compound lock. Parallel borrowed reads and separately closeable registrations require caller lifetime evidence; these are API/resource questions with no PHP finding program.
- Which published fastutil-core artifact/version meets exact required operations against JDK, with HPPC as the second candidate? Verify and pin the candidate artifact coordinates/version/license before measuring it; compare that pinned candidate before selecting a dependency. No custom general-purpose table is selected, no dependency winner is measured, and ordered/cold JDK collections remain where suitable.
- Which external clients need particular views, handles or optional backends? JGraphT/MapDB/Neo4j retention and their persistence/resource contracts remain; no inventory or backend removal is complete. Caller-owned implementation selection defaults to the present path until separate acceptance; no silent fallback or additional feature switches.

## Pending Acceptance Measurements

Acceptance of each implementation requires comparison against the present implementation under identical JVM/heap settings; record exact revisions, query mix and complete outcomes. Structural byte formulas and historical partial timings are not total retained-heap or completed acceptance results. Record quantitative targets and the caller budget before implementation measurement; no percentage tolerance is selected here. Hash/capacity slack, adapter state, wrappers, dictionaries, exact/label indexes, active edits, payload sharing, notifications and workspace all count.

|---|---|---|
| Typed selection and identity | Fixed selected neighborhood; grow irrelevant kinds/names independently; count selected-edge acquisitions, row probes/copies, identity probes, insertion time and allocation/read | Equal semantic graph facts/observations, with zero extra selected-row reads from unrelated growth; stop on changed identity/order/observations or unrelated scanning. Retain existing pair/group indexes. |
| ID holes and lifetime | Fixed live size with increasing deletion holes/highest allocated ID; count capacity, map bytes, resize peak and access probes; exercise freeze/clear/stale handles | Stable surviving IDs, no wrapped/reused live ID and bounded accounted capacity; stop on stale-handle acceptance or hidden high-ID capacity growth that violates budget. |
| Row and mutable layout | 200k-node/199999-edge shapes at 0/1/3/6 properties, then captured row/degree distributions; vary irrelevant kinds/history independently; count visits, copies, index updates, boxing, retained heap and resize peaks | Exact semantics, a measured targeted layout win, no accepted-resource regression and no typed-read row copy; stop on resource regression, budget excess or indexes erasing savings. Measurements choose sorted/linear rows and vectors/lists. |
| Frozen layout and lifecycle | Small/large degree, sparse/dense active edits, deletion/import, repeated Freeze; count passes, time, complete retained heap, peak live/committed heap, per-entry copied bytes and clear notices | Within configured old+new+workspace budget, equal reads/identity/order/notices and prior state survives injected failure; stop before excess allocation or on incoherence/resource leak. Stop on mismatch/regression/incomplete run; partial timings establish no acceptance. Consumer owns driver choice and buffer/history/reference checks. |

Before the first three migration stages can pass: capability adapters must construct both paths with unchanged default/configuration and codec round trips; field/cell access must vary 1/100/10000 irrelevant names at a fixed two-property row; typed adjacency must cover both directions, self/parallel edges, deletion, empty results, layer/label selection, acquisition observations and compound-write atomicity. Later collection/record/CSR stages reuse those paths. Choosing a default or deleting superseded/optional implementations remains separate from implementing the candidate.
